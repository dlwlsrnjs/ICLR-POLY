# 여러 대상 모델에서 학습하는 선택기: 규모 수정

작성: 2026-09-03. 사용자 정정: 설정 10개와 모델 10개를 혼동하지 않으며,
여러 모델의 실제 평가 결과를 이용해 새 모델에 적용할 선택기를 학습한다.
아래 수집 규모는 설계 목표이며, 실행 완료나 충분한 표본 수의 증명이 아니다.

## 무엇을 학습하는가

여러 대상 모델을 환경으로 사용해 하나의 설정 선택 정책을 학습한다.
대상 모델 자체를 각각 강화학습시키는 것이 아니다. 기본 관측 단위는
`정확한 대상 revision × 원문 그룹 × 실제 구성 × 실행 seed/반복`이다.

한 행에는 모델 계열, 문항 split, 실제 언어 목록·조각화·배열을 복원할 수 있는
구성 ID, 프롬프트 해시, 응답 해시, 점수·판정 버전, 토큰 및 소요 시간을 보존한다.
같은 프롬프트를 모델마다 동일하게 사용하고, 필요한 chat template 및 생성 모드는
별도 기록한다. 모델 이름은 계보와 분할에 쓰며, 새 모델에는 없는 학습용 모델 ID
임베딩에만 의존하는 정책을 만들지 않는다.

정책은 지금까지 관측한 구성·결과와 남은 비용으로 다음 구성을 선택한다.
다양한 모델에서 결과를 예측하는 지도학습으로 초기화하고, 실제 관측이 확보된
구성에서만 순차 정책을 학습한다. 미관측 구성을 성능 예측값으로 채워 실제 결과로
취급하지 않는다. 무해 재구성 예측과 논문의 reconstruction-gated 안전성 평가를
구분하며, 전자만 완료하고 주 연구 목적의 학습·검증까지 끝났다고 보고하지 않는다.

## 수집 목표와 단계

- **대상:** 총 30개 안팎의 범용 텍스트 체크포인트, 10개 이상의 계열을 초기
  계획 목표로 둔다. 가능한 분할 목표는 학습 20 / 검증 5 / 최종 평가 5이지만,
  계열 중복 방지가 정확한 개수보다 우선한다. 30개 전체를 학습 모델 수라고 쓰지 않는다.
- **문항:** 모델당 수백 개의 원문 그룹에서 시작한다. 기존 원문과의 해시 중복,
  번역 대응, 이전 평가 노출을 확인한 뒤 실제 독립 분할 수를 고정한다.
- **구성:** 공통 비교용 후보 64개를 시작점으로 계획하고, 검증 자료의 비용·분산을
  보고 128/256개로 확장한다. 단순 조건 이름 추가가 아니라 서로 다른 실제
  언어 구성·조각화·배열이어야 하며, 프롬프트 중복을 제거한다.
- **수집 순서:** 호환성·비용 측정 → 여러 계열의 공통 후보 결과 확보 → 학습용
  대상과 구성 확대 → 검증에서 설계 동결 → 보류한 대상·원문에서 최종 평가.
  새 모델 접근·이용 조건과 저장 공간은 추가 확보 전에 확인한다.

규모 산정 예시로 30대상 × 800원문 × 64구성은 **1,536,000개 대상 호출**이다.
이는 전수 교차 실행의 비용 예시이며 현재 확보한 데이터 수나 승인된 일괄 실행
큐가 아니다. 반복 생성·판정 비용은 추가된다. 공통 비교 구간을 확보하면서
훈련 영역을 점진적으로 넓혀 실제 비용과 coverage를 함께 기록한다.

현재 캐시 12개는 초기 수집 재료다. 추가 대상 확보 및 실행 검증 없이 30개가
준비됐다고 말하지 않는다. 원문 행 수가 많아도 새로운 모델 계열의 다양성을
대신하지 못하며, 10모델이라는 숫자만으로 모든 선택기 학습이 불가능한 것도 아니다.

## 충분한 규모인지 확인하는 방법

1. 검증용 계열과 원문을 고정하고 학습 대상 수를 늘린다. 먼저 총 관측 예산을
   맞춰 다양성의 효과를 비교하고, 이어 모델당 수집량을 맞춘 결과도 따로 보고한다.
2. 대상 집합을 고정한 채 문항 수와 실제 구성 수를 늘려 효과를 각각 측정한다.
3. 같은 계열 내 새 크기·버전으로의 전이와 완전히 보류한 계열로의 전이를 구분한다.
4. 모델 이름·문항·구성 해시가 분할을 넘어 누출되지 않도록 검사한다. 같은 원문의
   번역과 조각 변형은 같은 split이며, 미래 평가 점수는 선택기의 입력에서 제외한다.
5. 고정 설정, 무작위 탐색, BO/밴딧, 1회 지도학습 선택기, 순차 정책을 같은 실제
   평가 비용에서 비교한다. 지도학습과 RL의 추가 학습 연산량 차이도 통제한다.
6. 학습 episode 수와 별도로 고유 대상 수, 계열 그룹 수, 원문 수, 구성 수,
   실제 관측 수를 보고한다. 불확실성을 수만 replay episode만으로 축소하지 않는다.

계열이 추가되어도 검증 성능이 계속 바뀐다면 목표 모델 수를 늘린다. 개선이
멈춰도 보류 계열의 평가가 충분하지 않으면 보편적 일반화를 주장하지 않는다.
