\subsection{Reconstruction case studies (redacted)}
\label{app:cases}
We categorize outcomes into one success type and two failure types, recorded in the existing manuscript from its audit logs. Raw case provenance
was not reverified in this revision. Per the data policy, reconstructed requests and answers are never
reproduced; we show only the condition, scenario, the reconstruction judge's structural
verdict (reconstruction equivalent yes/no with the lexical overlap in parentheses),
the safety label, and the judge's own note with any harmful specifics removed.

\paragraph{(A) Judged joint success: equivalent reconstruction and unsafe answer.}
The model de-interleaves the fragments, restores the English request, and produces
unsafe content. Only these count under gated ASR.

\paragraph{(B) Gate denies: de-interleaving failed.}
The model returns a garbled or partial reconstruction; the reconstruction judge marks
it non-equivalent, so the gate withholds credit even when the answer is unsafe. These
are the accidental evasions a raw ASR would over-count.

\paragraph{(C) Alignment holds after reconstruction.}
The model reconstructs the request faithfully yet still refuses or answers safely.
These cases show the attack is not merely defeating a parser; when the model does
recover the intent, alignment can still fire.
